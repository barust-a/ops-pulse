# Ops Pulse v0.1.0 — release notes

**Date:** 2026-10-10 · **Type:** first release (minor) · **Images:** `api`, `web`, `kpi-job` tagged
`v0.1.0` in the project registry

First deployable version of Ops Pulse, the modernised replacement for the SupervIT v1
supervision application (fictional baseline, see the [legacy analysis](../analysis/legacy-analysis.md)).

## For users

- New web application in French with three pages: "Vue d’ensemble", "Incidents", "Changements".
- Daily indicators per service: MTTR, 90th-percentile resolution time ("Résolution p90"), SLA
  breach rate, change failure rate, and automatic detection of unusual incident volumes
  ("Anomalies détectées").
- New charts: daily volume with anomaly markers, MTTR and SLA by priority, opening heatmap by
  weekday and hour, change failure rate and close codes by service.
- Incident list with server-side filters (period, service, priority, state, search) and paging;
  analysts can declare and update incidents.
- Secure sign-in with roles "Lecteur", "Analyste", "Administrateur".

User guide: [docs/handbook/user-guide.md](../handbook/user-guide.md).

## For operators

- Docker images on Red Hat UBI 9, non-root; Docker Compose stack with a production override
  (read-only containers, resource limits, log rotation).
- systemd units for the stack, the daily 06:00 KPI job and the 05:30 database backup.
- Scripts: `deploy.sh` (pull, migrate, start, health wait, smoke test), `rollback.sh`,
  `backup-db.sh`. Nginx and Apache virtual hosts for host-level reverse proxying.
- Install: [installation guide](../ops/installation.md); runbook: [operations](../ops/operations.md).

## For developers

- API `/api/v1` documented with OpenAPI 3.1 (`/api/v1/docs`); JWT auth; zod validation.
- Database schema `ops` (PostgreSQL 16) with migrations `0001_init`, `0002_indexes`.
- Dataiku project with SQL + Python recipes and a local runner; KPI library with tests.
- GitLab pipeline lint → test → build → package → deploy with JUnit and coverage reports.

## Upgrade / installation notes

- New installation only (no previous version). Create `deploy/compose/.env` from
  `.env.example` with real secrets; `SEED_DEMO_DATA` must stay `false` outside demos.
- Migrations applied: `0001_init.sql`, `0002_indexes.sql`.

## Known limitations

- SAML 2.0 SSO is prepared but disabled (`SAML_ENABLED=false`): local accounts only.
- The ServiceNow incremental sync is designed ([ServiceNow integration](../handbook/servicenow-integration.md))
  but not yet implemented: data comes from the seed or a one-off import.
- Account management has no UI yet (platform team creates accounts).
- Retention purge is manual; no browser end-to-end or load tests yet ([test strategy](../testing/test-strategy.md#5-not-automated-yet)).
